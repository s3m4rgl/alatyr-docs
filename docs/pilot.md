# Пилот: с чего начать

Короткий маршрут для администратора, который разворачивает пилот Alatyr на
выпуске **v1.5.5**: сервер одной командой, агент на Windows и macOS,
одобрение устройств мышью в админке, выдача трёх целей — `ssh`, `user_mtls`
и `vpn`. Подробности каждого шага — на страницах, на которые ведут ссылки;
здесь только порядок и то, что проверить.

## 1. Что в комплекте и что нужно заранее

### Файлы выпуска

Всё берётся со страницы выпуска
[v1.5.5](https://github.com/s3m4rgl/alatyr-docs/releases/tag/v1.5.5):

| Файл | Что это |
|---|---|
| `alatyr-deploy-1.5.5.tar.gz` | набор развёртывания сервера: Docker Compose, сценарий `first-up.sh`, `.env.example` с уже вписанной версией образов, `README.md` |
| `alatyr-agent-1.5.5-x64.msi` | агент для Windows (x64): служба, окно агента, драйвер считывателя |
| `alatyr-agent-1.5.5.pkg` | агент для macOS: подписан и нотаризован Apple, окно агента внутри |
| `alatyr-agent_1.5.5_amd64.deb`, `alatyr-agent_1.5.5_arm64.deb` | агент для Debian и Ubuntu |
| `alatyr-agent-1.5.5-1.x86_64.rpm`, `alatyr-agent-1.5.5-1.aarch64.rpm` | агент для Fedora, RHEL и совместимых |
| `alatyr-1.5.5.tgz` | Helm-чарт для установки сервера в Kubernetes |

Образы сервера и админки (`s3m4rgl/alatyr-server` и
`s3m4rgl/alatyr-frontend`) скачиваются сами при первом запуске: их версия
уже вписана в набор. Номер версии образов отличается от номера выпуска —
так и должно быть, берите их парой из одного выпуска.

Linux-агент и установка в Kubernetes поддерживаются, но в этом пилоте не
в фокусе: маршрут ниже — про Windows и macOS.

### Что нужно заранее

| Что | Требование |
|---|---|
| Машина под сервер | Linux с Docker 24.0+ (`docker compose` подкомандой), 2 ядра, 2–4 ГБ памяти, 20 ГБ диска — подробнее в [Установке](installation.md#что-нужно-перед-началом) |
| Порты сервера | `3000` — админка, `8090` — API для агентов, `8200` — списки отзыва и сертификаты УЦ для агентов. `8090` и `8200` должны быть открыты из сети, где стоят машины сотрудников |
| Вход в админку | без TLS перед сервером вход работает **только с самой машины сервера** по `http://localhost:3000`: по `http://<адрес>` браузер не сохраняет cookie входа, и форма молча возвращает на себя. Для входа с другой машины нужен обратный прокси с TLS (см. `README.md` набора) либо SSH-туннель до порта `3000` |
| Время | синхронизировано на сервере и на машинах сотрудников |
| Windows | проверены **Windows 10 LTSC** и **Windows 11**, x64, TPM 2.0. На Windows без интернета (LTSC) для окна агента нужен WebView2 Runtime: положите офлайн-установщик `MicrosoftEdgeWebView2RuntimeInstallerX64.exe` рядом с MSI — пакет поставит его сам |
| macOS | macOS 12 или новее. Пакет подписан и нотаризован, но **установку на чистый Mac мы своими руками ещё не проводили** — если что-то пойдёт не так, сообщите нам (раздел 5) |
| VPN-клиент | Windows — community **OpenVPN GUI** 2.6 (openvpn.net); macOS — `openvpn` 2.5+ из командной строки (`brew install openvpn`) |
| Свой сервер для проверки | Linux-машина с `sshd` для проверки `ssh`; веб-приложение за nginx или haproxy для `user_mtls`; OpenVPN-сервер для `vpn` |

## 2. Порядок разворачивания

1. **Сервер.** Распакуйте набор и выполните `./first-up.sh` — он придумает
   все пароли и ключи и напечатает их одним блоком: **сохраните этот блок
   сразу**. До первой выдачи впишите в `.env` адрес
   `ALATYR_PKI_PUBLIC_ADDR` (адрес этой машины с портом `8200`) и выполните
   `docker compose up -d`. Всё — в
   [Установке → Сервер](installation.md#сервер) и в `README.md` набора
   (разделы «Запуск» и «Первые шаги после запуска»).
2. **Вход в админку.** `http://localhost:3000` на машине сервера, логин и
   пароль из блока `first-up.sh`. Смените пароль администратора.
3. **Издатели и цели.** В «Настройки → Удостоверяющие центры» издатели
   `user_mtls` и `vpn` уже настроены набором; профиль **SSH** нужно включить
   самому и вписать, под какими учётными именами разрешён вход (`README.md`
   набора, шаг «Издатель для цели ssh»; подробно — [SSH → Настройка](ssh/setup.md)).
   Затем «Настройки → Политика выдачи» — включите `ssh`, `user_mtls` и `vpn`:
   на свежей установке включён только Wi-Fi.
   Для Windows-машин без Windows Hello (например, LTSC без PIN и биометрии)
   переключите «Настройки → Безопасность по умолчанию → Аппаратное
   подтверждение использования SSH-ключа» на «Предпочтительно» — при
   умолчании «Обязательно» `ssh` на таких машинах не выдаётся.
4. **Агент на Windows.** Установите доверие к издателю пакета и поставьте
   MSI с адресом сервера и доменом —
   [Установка → Windows](installation.md#windows). Адрес сервера —
   адрес API: `https://…` вашего TLS-прокси либо, для пилота в закрытой
   сети, `http://<сервер>:8090`. Без TLS агент работает, но предупреждает,
   что его секреты и заявки идут по сети открытым текстом.
5. **Агент на macOS.** Готовый `.pkg` из выпуска ставится вместе с файлом
   предварительных значений — блок для копирования в
   [Установка → macOS](installation.md#macos). На Mac нужен вход
   сотрудника в графическую сессию: без неё сертификат не выпустится.
6. **Одобрение устройства.** Зарегистрировавшаяся машина появляется в
   админке, а в «Запросах назначений» — её просьба о цели. «Разрешить» —
   и затем одобрите саму заявку в «Запросах». Роли и что проверяется при
   одобрении — [Управление и роли](administration.md#одобрение-отклонение-и-отзыв).
7. **Назначение целей.** «Устройства» → раскрыть строку машины →
   «Разрешённые назначения сертификатов»: отметьте `ssh`, `user_mtls`, `vpn`
   и сохраните. Сотрудник может и сам попросить цель кнопкой «Запросить» в
   [окне агента](agent-window.md) — просьба придёт в «Запросы назначений».
   Каждая выдача — отдельная заявка в «Запросах», её одобряете вы.
   Изменения доезжают до агента очередным тактом, в пределах десяти минут.

## 3. Что проверить в пилоте

Каждый сценарий — на Windows и на macOS.

| Цель | Действие | Ожидаемый результат |
|---|---|---|
| — | Открыть окно агента из значка в системной панели (Windows) или строке меню (macOS) | Видны цели и их состояния; у выданных — «выдан» |
| — | Выполнить `alatyr-agent status` (путь — в разделе 5) | Устройство зарегистрировано, видны идентификатор и срок сертификата |
| `ssh` | Положить на свой Linux-сервер открытый ключ SSH-УЦ и строку `TrustedUserCAKeys` ([SSH → Настройка](ssh/setup.md#шаг-5-настройте-ваш-сервер)); на машине сотрудника выполнить `ssh-add -l`, затем `ssh <логин>@<сервер>` | В `ssh-add -l` есть ключ с пометкой `alatyr-agent`; вход проходит без пароля, в журнале `sshd` — `Accepted publickey … ECDSA-CERT` ([шаг 6](ssh/setup.md#шаг-6-направьте-ssh-сотрудника-на-ключ-в-чипе)) |
| `user_mtls` | Одобрить заявку `user_mtls`; на Windows открыть `certmgr.msc` → «Личное» → «Сертификаты», на macOS — «Связка ключей» → связка входа пользователя | Сертификат сотрудника в хранилище **пользователя** (не машины), издатель — `Alatyr User mTLS Issuing CA` |
| `user_mtls` | Открыть в браузере сотрудника приложение за приёмником mTLS ([mTLS → Настройка](mtls/setup.md#шаг-5-настройте-ваше-приложение)) | Приложение пускает и видит личность сотрудника; сертификат `wifi` той же машины получает `403` ([шаг 6](mtls/setup.md#шаг-6-проверьте-обе-половины)) |
| `vpn` (Windows) | Выполнить `alatyr-agent.exe vpn --identity <почта>` от имени сотрудника, вписать строку `cryptoapicert` в профиль `.ovpn`, положить профиль в `C:\Program Files\OpenVPN\config\` и подключиться из OpenVPN GUI ([VPN → Windows](vpn/setup.md#windows)) | Значок OpenVPN GUI зелёный, в журнале клиента `Initialization Sequence Completed`, на VPN-сервере — имя сотрудника; PIN не спрашивается |
| `vpn` (macOS) | Выполнить `alatyr-agent vpn`, вписать напечатанные строки в профиль, поднять `sudo openvpn --config <профиль>` и в сеансе сотрудника `alatyr-agent vpn serve-key` ([VPN → macOS](vpn/setup.md#macos)) | Туннель поднимается, ключ не покидает Secure Enclave |
| любая | Отклонить заявку, затем «Выписать цель» заново в окне агента (или `alatyr-agent reissue <цель>`) | Появляется новая заявка, после одобрения цель выдаётся |

## 4. Известные ограничения v1.5.5

Общий список продукта — [Известные ограничения](limitations.md). Для пилота
важно следующее:

- **Профиль `.ovpn` агент не пишет.** Его составляете вы (пример — на
  странице [VPN → Настройка](vpn/setup.md#профиль-целиком-и-куда-его-положить))
  и кладёте на машину вручную или политикой раскатки.
- **Только OpenVPN GUI на Windows и `openvpn` из командной строки на
  macOS.** OpenVPN Connect не поддерживается на обеих системах, Tunnelblick
  как графический клиент — тоже ([почему](vpn/caveats.md#openvpn-connect-не-берёт-ключ-из-чипа)).
  Профиль в пользовательском каталоге Windows требует группы
  `OpenVPN Administrators` ([подробнее](vpn/caveats.md#профиль-из-пользовательского-каталога-требует-группы-openvpn-administrators)).
- **macOS: установку `.pkg` на чистый Mac мы ещё не проходили целиком**, и
  полный цикл выдачи `vpn` на Mac — тоже. Пакет нотаризован, окно агента и
  туннель проверены по отдельности.
- **macOS: полной очистки клиента (`wipe-client`) нет.** Переустановка
  поверх работает; чистое удаление со всеми данными — пока вручную.
- **Не меняйте удостоверяющие центры и издателей после первой выдачи.**
  Смена корневого УЦ или издателя цели на работающей установке сейчас
  ломает выдачу: агенты отказываются от новой цепочки, а заявки перестают
  одобряться. Если это случилось — напишите нам, не переустанавливайте всё
  подряд.
- **Отзыв `user_mtls` и `vpn` действует через список отзыва на вашем
  приёмнике** (`crl-verify` в OpenVPN, проверка CRL в nginx/haproxy), а не
  сам по себе ([VPN → нюансы](vpn/caveats.md#отзыв-действует-только-через-crl-verify-на-вашем-сервере)).
- **Сертификат `vpn` сам не перевыпускается** по истечении срока —
  [подробнее](vpn/caveats.md#сертификат-цели-vpn-сам-не-перевыпускается).
- **В журнале `sshd` у сертификата виден служебный Key ID** вида
  `vault-token-…` вместо имени сотрудника. На вход не влияет.
- **Windows: в журнале агента на свежей установке на каждом такте
  повторяется предупреждение** о владельце каталога передачи («владеет не
  SYSTEM»). На работу не влияет.
- **Карточка подтверждения в админке узкая** — длинный текст переносится
  посреди фразы.
- **Linux и Kubernetes** поддерживаются, но в v1.5.5 цель `vpn` на Linux и
  доступ к Kubernetes с Windows не выдаются.

## 5. Как сообщить о проблеме

Соберите и приложите к сообщению:

1. **Что делали и что увидели** — шаг из этой страницы, время (UTC) и текст
   ошибки или снимок экрана админки / окна агента.
2. **Состояние агента** — вывод команды `status` (и `purposes`, если дело в
   целях):

    ```powershell
    # Windows, PowerShell
    & "C:\Program Files\AlatyrAgent\alatyr-agent.exe" status
    ```

    ```bash
    # macOS
    /Applications/alatyr-agent.app/Contents/MacOS/alatyr-agent status
    ```

3. **Журналы агента.** Их два — машинный и пользовательский, и цель
   `user_mtls`/`vpn`/`ssh` чаще видна во втором
   ([подробнее](logging.md#у-агента-две-половины-и-журналов-тоже-два)):

    | Система | Машинный журнал | Пользовательский журнал |
    |---|---|---|
    | Windows | `C:\ProgramData\AlatyrAgent\agent.log` | `%LOCALAPPDATA%\AlatyrAgent\user-agent.log` |
    | macOS | — (агент целиком работает от пользователя) | `~/Library/Logs/AlatyrAgent/agent.log`, рядом `sshagent.log` |

    Журнал установки MSI — если ставили с `/l*v C:\Windows\Temp\alatyr-msi.log`;
    на macOS — `/var/log/install.log`.

4. **Журнал сервера** за время проблемы, из каталога набора:

    ```bash
    docker compose logs --since 1h server > alatyr-server.log
    ```

    и версию сервера: `curl -s http://localhost:8090/api/v1/version`.

Перед отправкой уберите из файлов пароли и токены, если вы вписывали их в
команды.

**Куда писать:** контакт поддержки — укажет команда.

Порядок разбора типичных симптомов — [Диагностика](troubleshooting.md).
